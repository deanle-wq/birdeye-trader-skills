# Exit and rotation workflow

1. Use `birdeye-track exit` to reconstruct where observable activity went after a wallet reduced a named token.
2. Use `birdeye-track rotation` when the question is specifically what the same wallet bought next.
3. Keep wallet, token and time window explicit. Separate swaps from transfers when the evidence permits.
4. Report temporal sequence and coverage; do not claim causal fund flow without direct linkage.
5. Add `birdeye-token-dd run` only when the user asks to evaluate the destination token.
