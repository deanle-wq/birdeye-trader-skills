# Wallet analysis workflow

1. Use `birdeye-wallet activity` for a factual activity request.
2. Use `birdeye-wallet-analysis run` when the user asks about style, timing, repeatability or whether the wallet is worth monitoring.
3. Use `birdeye-wallet-score run` only when the user asks about copyability; preserve their position-size and latency assumptions.
4. Use `birdeye-wallet compare` when two or more explicit wallet addresses must be evaluated on the same window and metrics.
5. State that traded tokens are not complete current holdings and that reconstructed PnL is limited to covered indexed trades.
